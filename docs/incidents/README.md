# docs/incidents/

Auto-generated incident post-mortem documents. Files in this directory are created and committed automatically by the AI platform agent (`platform/ai`) whenever an incident is processed.

## File Naming Convention

```
YYYY-MM-DD-<slug>.md
```

Where `<slug>` is a kebab-case truncation of the incident summary (max 50 characters).

Example: `2026-03-19-type-error-in-auth-middleware-during.md`

## File Contents

Each incident document contains:

| Section | Description |
|---|---|
| Metadata table | Date, type, severity, service, GitHub issue link |
| Summary | One-line incident description from Claude analysis |
| Root Cause | Technical explanation of what went wrong |
| Impact | User/system impact assessment |
| Resolution | Suggested fix or action items |
| Context | Type-specific details (CI: workflow/branch/commit; Security: CVE/package; Sentry: error/route) |

## Generation

Incident docs are generated by `platform/ai/src/actions/incident-doc.ts` via `generateAndCommitIncidentDoc()`. The function:
1. Builds a Markdown document from the normalized event and Claude analysis result
2. Commits it to the repository via the GitHub API using the `GITHUB_TOKEN`
3. Returns the file path, which is stored in the `IncidentRecord` in Redis for dashboard linking

## Usage

Incident docs linked from the `/platform/incidents` dashboard provide full historical context for every processed event. Links point to `https://github.com/{GITHUB_REPO}/blob/dev/{incidentDocPath}`.

Do not manually edit or delete files in this directory — they serve as the audit trail for the platform's incident history.
